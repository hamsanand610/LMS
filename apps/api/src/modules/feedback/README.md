# feedback module

Feedback (F-18, Roadmap Phases 3–4, decision D10): an administrator gives a form to a batch, once
or every week from Friday to Sunday; its learners answer, anonymously unless the form says
otherwise; the trainer a form is about reads its figures.

| Aspect       | Detail                                                                                                                                                                                                                                                                                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes       | `GET/POST /feedback/forms`, `GET /feedback/forms/:id`, `POST /feedback/forms/:id/close`, `GET /feedback/forms/:id/results?period=`; learners `GET /me/feedback`, `POST /me/feedback/:id/responses` (30 an hour per person)                                                                                                                                                       |
| Permissions  | `feedback:manage` (administrators, `all`): give and close forms, read everything; `feedback:read` (`all`, or `own` for a trainer: the forms naming them); `feedback:respond` (learners, `own`), as the requirements' matrix sets it                                                                                                                                              |
| Flag         | `module.feedback`, off by default; the demo overlay switches it on. Off, every route answers 403 `module_disabled`                                                                                                                                                                                                                                                               |
| Rounds       | `once`: between the form's opening and closing. `weekly`: each Friday 00:00 to Monday 00:00 in the institute's time zone (AC-13.1), from the form's start until it stops; a round is named by its Friday (`YYYY-MM-DD`)                                                                                                                                                          |
| Notices      | `feedback.announce` (every 15 minutes, and on creation) tells the batch once per round that a form is open (`feedback.open`, in the app)                                                                                                                                                                                                                                         |
| Anonymity    | An anonymous answer is stored with no learner, a random (version 4) id and the day only. A keyed hash of form, round and learner (HMAC-SHA-256 under a key derived with HKDF from the signing secret) refuses a second answer (409 `feedback_answered`) without naming the first. Answering is not audited, so the audit log does not place a learner beside an answer (AC-13.2) |
| Figures      | Below five answers in a round only the counts are given: no average, chart or comment (D10). Comments are listed in random order; on a named form administrators see the names, nobody else does                                                                                                                                                                                 |
| Known limits | Someone holding both the database and the signing secret could recompute a learner's token; rotating the signing secret lets a learner answer an open round once more. Reminders before a round closes are not sent yet                                                                                                                                                          |
| Tests        | `test/feedback.e2e-spec.ts` (who gives forms, who answers, one answer each, nameless storage, the five-answer rule, names on named forms, a trainer's own forms, closing, one notice per round); shared `feedback.spec.ts` (the weekly round, form rules)                                                                                                                        |

**Figures elsewhere.** The reports and the dashboard read feedback through the same rule: whole
rounds only, chosen by the round's date and never split by the day an answer came in, each
counted once it has five answers, and only for `feedback:read` holders. A trainer's filter
narrows the forms about them and never reaches another trainer's (security review M1, M2;
`test/feedback.e2e-spec.ts`).
