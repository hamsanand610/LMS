# assignments module

Assignments: questions from the bank, grouped into modules, given to a batch or to named learners,
answered in one workspace, checked on the server and reviewed by trainers (journeys J-06, J-09;
Task 4, ADR-0016).

| Aspect        | Detail                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Staff routes  | `GET/POST /assignments`, `GET /assignments/analytics`, `GET/PATCH/DELETE /assignments/:id`, `PUT …/structure`, `PUT …/resources`, `GET …/resources/:resourceId/link`, `GET …/publications`, `POST …/publish`, `DELETE …/publications/:publicationId`, `GET …/progress`                                                                                          |
| Review routes | `GET /submissions` (the review queue), `GET /submissions/:id`, `POST /submissions/:id/reviews`, `POST /submissions/:id/re-evaluate`, `GET /submissions/:id/files/:fileId/link`                                                                                                                                                                                  |
| Learner       | `GET /me/assignments` (search, filters, sorting, paging, summary, facets), `GET /me/assignments/:id`, `GET …/resources/:resourceId/link`, `GET …/questions/:placementId`, `GET …/questions/:placementId/submissions`, `POST …/run` (40 per 5 min), `POST …/submissions` (30 per 5 min), `GET /me/submissions/:id`, `GET /me/submissions/:id/files/:fileId/link` |
| Permissions   | `assignments:read`, `assignments:submit` (own), `assignments:manage`, `assignments:publish`, `assignments:grade`; manage, publish and grade take scope `all` or `batch`, and a batch-scoped trainer reaches only the batches and learners they teach (`reach.ts`)                                                                                               |
| Kinds         | Nine question types in one submission model: objective (single, multiple, true/false), written, coding, SQL, file upload, practical, project                                                                                                                                                                                                                    |
| Structure     | `PUT …/structure` replaces the whole thing. A question that stays in a module keeps the answers already given to it, because placements are matched by question, not by position; a placement with submissions cannot be removed                                                                                                                                |
| Unlocking     | A module opens `always` or `after_previous` at a percentage of the questions solved. The rule is enforced on the question endpoint as well as shown, so a locked question cannot be reached by guessing its id (`module_locked`, plan AC-06.2)                                                                                                                  |
| Publishing    | To a batch or to named learners, with optional open, due and close dates (`assignmentPublishSchema`). Everyone it reaches is told. The same batch twice is refused (`already_published`); an assignment with no questions cannot be published                                                                                                                   |
| Status        | Worked out on the server for each learner (`learner-state.ts`): upcoming, not started, in progress, submitted, passed, failed, completed, overdue, locked. Never stored, never taken from the client                                                                                                                                                            |
| Run, submit   | Run checks the visible cases (or the learner's own input) in the sandbox and records nothing. Submit writes an immutable submission; objective answers are marked at once, code is queued (`assignments.evaluate`, idempotent, retried while the sandbox is unavailable) and checked against every case                                                         |
| Hidden cases  | Never sent to the browser. A learner sees a hidden case as a verdict and a cost only; reviewers see everything                                                                                                                                                                                                                                                  |
| Attempts      | `attemptsPerQuestion` limits re-tries; zero means unlimited. Every attempt is kept, and the best one counts (plan AC-06.3)                                                                                                                                                                                                                                      |
| Reviews       | Append-only decisions (`graded`, `approved`, `resubmission_requested`, the last needing a comment); the submission itself never changes, the effective marks are cached on it, and the learner sees the decision and comment                                                                                                                                    |
| Explanation   | `after_solve` reveals the worked answer once the learner gets it right, `after_due` after the due date, `never` not at all. Before that the workspace shows no explanation and no correct option                                                                                                                                                                |
| Figures       | The learner's page, the staff progress table and the progress module all compute solved and marks the same way, from the best attempt at each question (plan AC-06.4); analytics add pass rate, average score, overdue work and struggling learners                                                                                                             |
| Events        | `assignment.published`, `submission.created`, `submission.evaluated`, `submission.graded`                                                                                                                                                                                                                                                                       |
| Audit         | `assignment.created`, `assignment.updated`, `assignment.structure_saved`, `assignment.resources_saved`, `assignment.archived`, `assignment.published`, `assignment.withdrawn`, `submission.created`, `submission.reviewed`, `submission.re_evaluated`                                                                                                           |
| Tests         | `learner-state.spec.ts`; `test/assessment.e2e-spec.ts` (authoring, publishing, gating, attempts, run and submit, hidden cases, reviews, scope and deny cases); `apps/web/e2e/assessment.spec.ts` (the browser journeys)                                                                                                                                         |

## Phase 2 (2 October 2026)

- **Late work** is recorded on the submission (`isLate`) when it is accepted after the learner's due
  date, and shown in the result.
- **The answer key (D7).** Under `after_due` the key and explanation appear only once the due date
  has passed _and_ the learner can answer no more (no attempts left, solved, or closed for them), so
  a late last attempt is never copied from the key (`revealAnswers`).
- **The attempt limit** is counted again inside the transaction that writes the submission; parallel
  submits collide on the attempt number and the loser finds the limit reached. A sandbox error is
  not an answer and does not use an attempt.
- **Runs** go through the per-person execution gate (ADR-0021), as the Labs do.
- **Projects (D6).** `GET /me/assignments?questionType=project` lists the assignments that hold a
  project question; the Projects page reads it. No new tables.
- **Reminders.** `assignments.due-reminders` (hourly at :15) tells each learner who has not handed
  everything in, once per publication, when it falls due within a day.
- **Tests:** `test/learner.e2e-spec.ts` (late work, the key, the race); `reveal-answers.spec.ts`.
