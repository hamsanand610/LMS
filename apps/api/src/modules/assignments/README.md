# assignments module

Practice sets: questions from the bank, grouped into modules and given to a batch (journeys J-06, J-09).

| Aspect      | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes      | `GET/POST /assignments`, `GET/PATCH/DELETE /assignments/:id`, `PUT /assignments/:id/structure`, `GET /assignments/:id/publications`, `POST /assignments/:id/publish`, `DELETE /assignments/:id/publications/:publicationId`, `GET /assignments/:id/progress`, `GET /assignments/grading/queue`, `POST /submissions/:id/grade`; learner: `GET /me/assignments`, `GET /assignments/:id/me`, `GET /assignments/:id/questions/:placementId`, `GET …/cases`, `POST …/submissions` |
| Permissions | `assignments:read`, `assignments:submit` (own), `assignments:manage`, `assignments:publish`, `assignments:grade`; the manage, publish and grade permissions take scope `all` or `batch`                                                                                                                                                                                                                                                                                      |
| Structure   | `PUT …/structure` replaces the whole thing. A question that stays in a module keeps the answers already given to it, because placements are matched by question, not by position                                                                                                                                                                                                                                                                                             |
| Unlocking   | A module opens `always` or `after_previous` at a percentage of the questions solved. The rule is enforced on the question endpoint as well as shown, so a locked question cannot be reached by guessing its id (`module_locked`, plan AC-06.2)                                                                                                                                                                                                                               |
| Attempts    | `attemptsPerQuestion` limits re-tries; zero means unlimited. Every attempt is kept, and the best one counts (plan AC-06.3)                                                                                                                                                                                                                                                                                                                                                   |
| Marking     | Objective answers are marked the moment they arrive. A written answer waits in the grading queue. A coding answer is marked from the question's own cases and weights (ADR-0011)                                                                                                                                                                                                                                                                                             |
| Explanation | `after_solve` reveals the worked answer once the learner gets it right, `after_due` after the date, `never` not at all. Before that the workspace shows no explanation and no correct option                                                                                                                                                                                                                                                                                 |
| Publishing  | To one batch at a time, with an optional due date. Everyone in the batch is told. Publishing the same assignment to one batch twice is refused (`already_published`); an assignment with no questions cannot be published                                                                                                                                                                                                                                                    |
| Due dates   | `allow_late` lets an answer in after the date and records when it arrived; `block_late` refuses it (`assignment_overdue`)                                                                                                                                                                                                                                                                                                                                                    |
| Figures     | The learner's page, the staff progress table and the progress module all compute solved and marks the same way, from the best attempt at each question (plan AC-06.4)                                                                                                                                                                                                                                                                                                        |
| Events      | `assignment.published`, `submission.created`, `submission.graded`                                                                                                                                                                                                                                                                                                                                                                                                            |
| Audit       | `assignment.created`, `assignment.updated`, `assignment.structure_saved`, `assignment.archived`, `assignment.published`, `assignment.withdrawn`, `submission.graded`                                                                                                                                                                                                                                                                                                         |
| Tests       | `test/assessment.e2e-spec.ts` (J-06 and J-09 end to end, gating, attempt limits, grading, agreement between the learner and staff views); `apps/web/e2e/assessment.spec.ts` (the browser journey)                                                                                                                                                                                                                                                                            |
