# settings module

Institute settings, branding and theme tokens, feature flags and navigation overrides — the
configuration layer of the white-label template (architecture plan §16, §22).

| Aspect      | Detail                                                                                                                                                                                                                                                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes      | `GET/PATCH /settings`; `GET /branding/public` (public, ETag), `GET /branding`, `PATCH /branding`, `POST /branding/preview`; `GET /flags`, `PATCH /flags/:key`; `GET/PATCH /navigation/:portal`; `GET /taxonomies/:taxonomy/terms`, `POST /taxonomies/:taxonomy/terms`, `PATCH/DELETE /taxonomies/:taxonomy/terms/:id`; `GET/POST /custom-fields`, `PATCH/DELETE /custom-fields/:id` |
| Permissions | `settings:read`, `settings:manage`, `branding:manage`, `flags:manage`                                                                                                                                                                                                                                                                                                               |
| Settings    | Sections `general`, `academic`, `legal` validated by `settingsSchema` (`@lms/shared`), stored one JSON row per section                                                                                                                                                                                                                                                              |
| Branding    | Seeds (`brandingSeedsSchema`) → `deriveTokens` → contrast-validated tokens for light and dark schemes, stored with a version; the web app injects them as CSS variables; emails read `emailBrand()`                                                                                                                                                                                 |
| Flags       | Manifest defaults joined with stored overrides; `module.<key>` flags gate whole modules (`ModuleEnabledGuard`), option flags gate behaviour; core modules are locked                                                                                                                                                                                                                |
| Navigation  | Manifest items filtered by permission and flags, then per-portal overrides (label, order, hidden, icon)                                                                                                                                                                                                                                                                             |
| Caches      | 30 s in-memory caches, cleared on write                                                                                                                                                                                                                                                                                                                                             |
| Events      | `branding.changed`, `flag.changed`, `navigation.changed`                                                                                                                                                                                                                                                                                                                            |
| Audit       | `settings.updated`, `branding.updated`, `flags.updated`, `navigation.updated`, `settings.term_created`, `settings.term_updated`, `settings.term_deleted`                                                                                                                                                                                                                            |
| Tests       | `packages/shared/src/theme/derive.spec.ts` (token derivation and contrast), `test/settings.e2e-spec.ts` (re-theme, preview, validation, settings, health)                                                                                                                                                                                                                           |

Client defaults live in `clients/<key>/*.json` and are applied by the base seed only when no value
exists yet; the admin UI always wins afterwards.

## The institute's own words and wiring (Phase 6)

| Aspect          | Detail                                                                                                                                                                                                                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Content pages   | `GET/POST /content-pages`, `PATCH/DELETE /content-pages/:id` for staff; `GET /pages/:slug` is public and returns only a published page — a draft reads as missing to a visitor. The demo ships terms and privacy                                                                              |
| Email wording   | `GET /templates`, `PATCH /templates/:key`, `DELETE /templates/:key` (back to the platform's own), `POST /templates/:key/test`. The layout, the button and the footer stay the platform's; the subject line and the message are the institute's, because that is what differs between clients  |
| Variables       | A template may use only the names it declares. A save that would render `{{whatever}}` into somebody's inbox is refused with the list of names it may use                                                                                                                                     |
| Where it lands  | Every send path resolves its wording before rendering, so an edit takes effect on the next invitation, reset or notification rather than only in the preview                                                                                                                                  |
| Integrations    | `GET /integrations`, `PATCH /integrations/:provider`, `POST /integrations/:provider/test`. A secret is write-only: stored, never returned, and the API says only whether one is present                                                                                                       |
| Honest about it | The running build takes its drivers from the environment at boot, not from these rows, so each card shows the driver actually in use as a fact and the stored row as the configuration a deployment would be given. A driver selector that silently changed nothing would be a page that lies |
| Rate limit      | `GET /branding/public` carries its own allowance. Every rendered page asks for it, and spending the default per-caller budget on a cached document would throttle a whole campus behind one address for doing nothing but opening pages                                                       |
| Audit           | `content_page.created`, `content_page.updated`, `content_page.deleted`, `email_template.updated`, `email_template.reset`, `email_template.tested`, `integration.updated` (never the secret, only whether one was set)                                                                         |
| Tests           | `test/settings.e2e-spec.ts` and `apps/web/e2e/self-service.spec.ts`                                                                                                                                                                                                                           |
