# courses module

Courses, their outline, the lessons a learner works through, and publishing (journey J-03).

| Aspect      | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes      | `GET/POST /courses`, `GET/PATCH/DELETE /courses/:id`, `PUT /courses/:id/outline`, `GET /courses/:id/publications`, `POST /courses/:id/publish`, `DELETE /courses/:id/publications/:publicationId`; `GET /lessons/:id`, `GET /lessons/:id/playback`, `GET /lessons/:id/resources/:resourceId/url`, `POST /lessons/:id/progress`, `POST /lessons/:id/complete`; `GET /lessons/:id/lab`, `POST /lessons/:id/lab/run`, `GET/POST /lessons/:id/lab/submissions`, `GET /lessons/:id/lab/submissions/:runId`; `GET /me/courses`; `POST /sessions/:id/recording` |
| Permissions | `courses:read` (scope `all`, `batch` or `own`), `courses:manage`, `courses:publish`; the two lesson-progress endpoints require `progress:read`, and attaching a recording requires `sessions:run`                                                                                                                                                                                                                                                                                                                                                        |
| Catalogue   | One list endpoint serves everybody: a caller with `courses:manage` sees drafts too, anyone else only what is published to them. `?batchId=` narrows it to what one batch has been given                                                                                                                                                                                                                                                                                                                                                                  |
| Outline     | `PUT /courses/:id/outline` replaces the whole structure in one transaction. Modules and lessons that keep their id keep their progress; anything the author left out is deleted. Positions are parked at negative values mid-transaction so reordering cannot collide on the unique index. A lab lesson must open a published lab that passes its own check, and a practice lesson a published question; only the references a save adds or changes are checked, so a lab withdrawn later never blocks an unrelated edit                                 |
| Lesson body | `content` is optional on save: an editor that never loaded a lesson's body sends none, and the stored body is kept. The web builder loads a body before it opens the editor for exactly this reason                                                                                                                                                                                                                                                                                                                                                      |
| Unlocking   | A module opens `always` or `after_previous` at a percentage. The rule is enforced on the lesson endpoint as well as shown on the course page, so a locked lesson cannot be reached by guessing its id (`module_locked`)                                                                                                                                                                                                                                                                                                                                  |
| Completion  | `watch` completes at `settings.academic.lessonAutoCompletePct`, `view` on opening, `manual` on the learner's word, `pass` (lab lessons only) when the lab is passed. "Mark complete" is refused for `watch` and `pass`. Figures come from the progress module, never recomputed here                                                                                                                                                                                                                                                                     |
| Publishing  | A publication names an audience (`all`, `program`, `batch`) and derives the enrolments through `EnrollmentService`. Publishing twice to the same audience is refused (`already_published`); a course with no lessons cannot be published (`course_has_no_lessons`)                                                                                                                                                                                                                                                                                       |
| Withdrawing | Ends the publication and removes only the enrolments with no progress, so a content decision never destroys someone's record. A course no publication reaches any more goes back to `draft`                                                                                                                                                                                                                                                                                                                                                              |
| Video       | `VideoService` hides the delivery driver. The demo uses `storage-file`: the object sits in the private bucket and plays through a four-hour signed URL. A hosted provider becomes a second driver without touching the lessons (ADR-0005)                                                                                                                                                                                                                                                                                                                |
| Recordings  | `POST /sessions/:id/recording` turns a class recording into an optional lesson in a course, gathered under one module per course, and links it back to the class. A second recording for the same class is refused (`recording_exists`)                                                                                                                                                                                                                                                                                                                  |
| Events      | `course.published`, `course.unpublished`, `recording.attached`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Audit       | `course.created`, `course.updated`, `course.outline_saved`, `course.archived`, `course.published`, `course.unpublished`, `session.recording_attached`                                                                                                                                                                                                                                                                                                                                                                                                    |
| Tests       | `test/courses.e2e-spec.ts` (J-03 end to end, reorder keeps ids, gating, withdrawal); `test/sessions.e2e-spec.ts` (recording attach); `test/labs.e2e-spec.ts` (lab lessons); `apps/web/e2e/learning.spec.ts` and `labs.spec.ts` (the browser journeys)                                                                                                                                                                                                                                                                                                    |

## A lesson that is a question (Phase 6, DP-S05)

| Aspect | Detail                                                                                                                                                                                                   |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes | `GET /lessons/:id/practice`, `POST /lessons/:id/practice/submissions`                                                                                                                                    |
| What   | A `practice` lesson carries a question id. The learner answers it where it stands, and getting it right completes the lesson — which is the point of putting a question in a course at all               |
| Types  | Only the types that can be marked without a person reading the answer. A coding or written question embedded in a lesson is pointed at the place that can mark it rather than accepted and left in limbo |
| Wrong  | A wrong answer leaves the lesson open, so it can be tried again; the explanation is shown once it is right                                                                                               |
| Demo   | The seed adds one practice lesson to Core Java, so the page has something behind it                                                                                                                      |

## A lesson that is a lab (Roadmap Phase 1, ADR-0018)

| Aspect     | Detail                                                                                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Routes     | `GET /lessons/:id/lab`, `POST /lessons/:id/lab/run`, `GET/POST /lessons/:id/lab/submissions`, `GET /lessons/:id/lab/submissions/:runId` (`courses:read`; runs and submissions rate-limited as in the Labs)                                 |
| What       | A `lab` lesson's content names a lab question. The learner opens it with the lesson's access rules (enrolled, module unlocked) and works on it exactly as in the Labs; everything runs in the sandbox                                      |
| Completion | Rule `pass`: a trusted submission that passes every case completes the lesson, made here or in the catalogue (the progress module's listener). Opening a lab lesson whose lab the learner already passed completes it too                  |
| Withdrawn  | A lab unpublished, retired or not passing its check after the lesson was saved is shown as unavailable (`lab_unavailable`), as is any lab while `module.practice` is off; the lesson page says so                                          |
| Placement  | Admins and content managers place labs in the outline (`courses:manage`); the editor offers only published labs that pass their check. The lesson's body is loaded with its lab, its video and its question, and saved back with all three |
| Demo       | The seed puts "Lab: fix the average" (a debugging lab) in Core Java and "Lab: finish the to-do list" (a web lab) in Web Development                                                                                                        |
